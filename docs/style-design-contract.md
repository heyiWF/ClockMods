# 表盘与日历样式契约（源码集成草案）

`com.clockmods.sdk.style` 是 View 与 Compose 共用的无 Android 依赖模型，使用 Java 8。
本轮并未发布独立 SDK/AAR，也不支持下载执行外部插件。现有表盘 API 与日历宿主适配器仍在应用内。

## 身份、数据与生命周期

- 表盘及日历元数据实现 `StyleIdentity`：稳定 ID、样式版本、最低 Android API，以及兼容性判断。
- ID 使用小写命名空间，如 `example.meridian`；注册时拒绝重复 ID，无法解析的已保存 ID 由宿主回退。持久化不能使用列表位置。
- 宿主负责时间、网络、日历计算、用户设置、字体解析和可见性。样式收到状态快照，不自行读取偏好或启动数据轮询。
- 表盘沿用 `ClockStyle` / `ClockState` / `ClockRenderContext`；日历沿用状态与能力声明，按声明获取所需日期明细。两类 renderer 保留各自的绘制接口。
- 退出页面、窗口隐藏或销毁时取消帧任务；静止阶段睡眠到下一次状态边界。恢复显示时重新请求绘制。

## 字体与空间

字体族、字重、时间/日期/辅助字号按样式 ID 独立保存；日历使用 `calendar:<id>` 作用域。
宿主将选定字体与倍率提供给样式，布局需按最终字体测量高度，避免按未缩放字号分配固定行高。
宜忌徽章固定，正文以 ` · ` 分项，溢出时保持字号并横向滚动；正文的完整内容必须保留在无障碍描述中。
有限屏幕无法保证任意字号和任意内容同时可见，应优先保留可读行高，将横向溢出交给滚动。

## 共用滚动策略

`MarqueeSpec` 是不可变值，可直接传入 View 或 Compose adapter；不能把 SharedPreferences 传给 SDK 绘制模型。

| 参数 | 默认 | 接口范围 | 设置预设 |
| --- | --- | --- | --- |
| speedDpPerSecond | 40 dp/s | 10–120 | 20 / 40 / 80 |
| pauseMillis | 1000 ms | 0–5000 | 0 / 1000 / 2000 |
| gapDp | 24 dp | 8–96 | 12 / 24 / 48 |

非法浮点配置回退默认值，超界值截断。输入几何应为有限非负像素，density 为有限正数；elapsed 为宿主单调时钟的相对毫秒。
每个日历主题独立保存；无旧值时行为与旧版一致。切换参数重置该行时间轴，不修改其他主题。
循环宜忌行使用 `loopDistance` / `loopOffset`：接缝至少为 1.5 倍字号，第二份正文无缝接替首份后停顿。
轮播页脚使用 `scrollOffset` / `holdMillis`：头尾停顿后切换项目，短行至少展示 3 秒；接缝间距仅对循环行有效。
`loopFrameDelay` / `scrollFrameDelay` 返回下一次绘制延时；`IDLE` 表示没有待执行帧，宿主不能把它当作普通延时提交。
轮播页脚还要取文字下一帧与项目切换边界的较小延时，切换动画期间按帧刷新。
旧 `CalendarMarqueeTiming` 保留为默认配置适配层。

## 对外 SDK 前仍需完成

抽离独立库与依赖清单、统一可本地化名称模型、公开日历 provider 注册入口、版本协商及能力/设置 schema、示例包与二进制兼容性检查。
当前日历资源 ID、宿主接口与 Compose 实现仍有应用依赖，不能将这个草案描述为已完成的第三方插件 SDK。
